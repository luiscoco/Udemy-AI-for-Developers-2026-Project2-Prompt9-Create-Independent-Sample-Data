# Contract Validation Smoke Tests

A polyglot monorepo with an Angular 22 frontend, a FastAPI backend and **one shared OpenAPI
contract**. The contract is the single source of truth: TypeScript types and Pydantic models
are generated from it, never written by hand.

At this stage the sample shows the **contract layer**: how one spec keeps two languages in
sync, how generated code is protected against drift, and how small smoke tests check it in both
ecosystems. The Angular app and FastAPI server are not scaffolded yet (their scripts are
`TODO` placeholders).

## Getting started

Requirements: Node.js 22 or newer, and [uv](https://docs.astral.sh/uv/) for Python 3.13.

```bash
npm run setup      # npm install + uv sync in apps/backend
npm run verify     # contract drift check, lint, typecheck, test and build (both ecosystems)
```

## Running on Windows

These commands work in Windows Terminal with PowerShell or Command Prompt. Run them from the
repository root, the folder that contains `package.json`.

### 1. Check the tools

```powershell
node --version    # must be v22 or newer
npm --version
uv --version      # install: winget install --id=astral-sh.uv -e
```

If `uv` was just installed, open a new terminal window so that it is on the `PATH`.

### 2. Go to the project folder

The path contains spaces, so put it in quotes:

```powershell
cd "C:\path\to\Prompt9"
```

### 3. Install dependencies (first time only)

```powershell
npm run setup
```

This runs `npm install` for the npm workspaces, then `uv sync` in `apps/backend`. `uv` downloads
Python 3.13 if it is not installed and creates `apps/backend/.venv`.

### 4. Start the app

```powershell
npm run dev
```

`dev` uses [`concurrently`](https://www.npmjs.com/package/concurrently) to start both halves in
one terminal. Each output line is prefixed with `[frontend]` (cyan) or `[backend]` (magenta).
Press `Ctrl+C` to stop both.

> **Current status:** the Angular app and the FastAPI server are not scaffolded yet, so both
> `dev` scripts are placeholders. Right now `npm run dev` prints the lines below and exits.
> There is no server to open in a browser yet.
>
> ```text
> [frontend] "TODO: ng serve (Angular 22 not scaffolded yet)"
> [backend] TODO: start FastAPI dev server
> ```
>
> Once they are scaffolded, the same `npm run dev` command will start both servers.

You can also start one half at a time:

```powershell
npm run frontend:dev
npm run backend:dev
```

### 5. What you can run today: checks and tests

```powershell
npm test           # Vitest (contract) + pytest (backend)
npm run verify     # drift check, lint, typecheck, test and build
```

`npm test` should end with `30 passed` from pytest. `npm run verify` exits with code 0 when every
step passes. In PowerShell, run `$LASTEXITCODE` afterwards to check it.

### Windows troubleshooting

| Problem | Fix |
| --- | --- |
| `npm.ps1 cannot be loaded because running scripts is disabled` | Run `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned` once, or use Command Prompt instead. |
| `uv` is not recognized | Install it with `winget install --id=astral-sh.uv -e`, then open a new terminal. |
| Messages from `uv` are shown in red as `NativeCommandError` | This happens in Windows PowerShell 5.1 when stderr is redirected (`2>&1`). `uv` writes normal progress messages to stderr, so these are not failures. Check `$LASTEXITCODE` instead. |
| Commands fail because the path is split at a space | Put the path in quotes, as in step 2. |

## How the contract flows

```text
                     packages/contract/openapi.yaml
                                  │
          ┌───────────────────────┴───────────────────────┐
  openapi-typescript                                datamodel-codegen
          │                                               │
  src/types.gen.ts  (TS unions)          app/generated/contract_models.py  (Pydantic v2)
          │                                               │
  src/index.ts                                    app/contracts.py
  (aliases + STATES/ACTIONS/PRIORITIES)          (re-exports + STATES/ACTIONS/PRIORITIES)
          │                                               │
  Angular frontend                                FastAPI backend
```

Application code imports only from the **public entry points** (`@equipment-maintenance-hub/contract`
and `app.contracts`), never from the generated files directly.

## 1. The OpenAPI spec

[packages/contract/openapi.yaml](packages/contract/openapi.yaml) describes the API (health,
assets, technicians, work orders, assignment, state transitions and a dashboard summary) and
every schema. The three enums are the core of the work-order domain:

```yaml
WorkOrderState:
  type: string
  description: Lifecycle state of a work order. `completed` and `cancelled` are final.
  enum: [reported, triaged, scheduled, in_progress, completed, cancelled]

WorkOrderAction:
  type: string
  enum: [triage, schedule, start, complete, cancel]

Priority:
  type: string
  enum: [low, medium, high, critical]
```

The lifecycle that connects states and actions is documented in the spec. A schema cannot
express it, so the backend will have to enforce it (not implemented yet):

```text
reported --triage--> triaged --schedule--> scheduled --start--> in_progress --complete--> completed
triaged --cancel--> cancelled,  scheduled --cancel--> cancelled
```

To change a shape, edit this file, then run `npm run contract:generate`.

## 2. TypeScript: generated types and runtime values

### Generated types

`openapi-typescript` turns each schema into a type inside a `components['schemas']` map
([src/types.gen.ts](packages/contract/src/types.gen.ts)). Enums become **string unions**:

```ts
WorkOrderState: "reported" | "triaged" | "scheduled" | "in_progress" | "completed" | "cancelled";
```

### Public aliases

[src/index.ts](packages/contract/src/index.ts) gives each schema a short name. Every alias
points into the generated map, so no shape is ever declared twice:

```ts
export type WorkOrderState = components['schemas']['WorkOrderState'];
export type WorkOrder = components['schemas']['WorkOrder'];
```

### Runtime enum arrays that the compiler keeps in sync

A union type disappears at runtime, but the UI needs actual values (dropdowns, guards,
iteration). So `index.ts` lists them, and a small helper makes the **type checker** confirm
that the list matches the union exactly:

```ts
type Missing<Union, Values extends readonly unknown[]> = Exclude<Union, Values[number]>;

const enumValues =
  <Union extends string>() =>
  <const Values extends readonly Union[]>(
    values: Values &
      ([Missing<Union, Values>] extends [never]
        ? unknown
        : { readonly missing: Missing<Union, Values> }),
  ): Values =>
    Object.freeze(values);

export const STATES = enumValues<WorkOrderState>()([
  'reported', 'triaged', 'scheduled', 'in_progress', 'completed', 'cancelled',
]);
```

How it works:

- **Curried call `enumValues<WorkOrderState>()(...)`**: you pass the union explicitly, and
  TypeScript still infers the array literal. A single call can't do both, because giving one
  type argument turns off inference for the other.
- **`const Values extends readonly Union[]`**: the `const` modifier infers the literal tuple
  (`readonly ['reported', ...]`) instead of `string[]`. `extends readonly Union[]` rejects any
  value that isn't in the contract, such as a typo or a value removed from `openapi.yaml`.
- **`Missing<Union, Values>`**: the union members that aren't in the array. If nothing is
  missing, the parameter type is `Values & unknown` (accepted). Otherwise it requires a
  `missing` property the array doesn't have, so compilation fails **and the error names the
  missing member**, for example `Property 'missing' is missing... 'cancelled'`.
- **`[X] extends [never]`**: wrapping in a tuple stops the conditional from distributing over
  the union, which is the standard way to test "is this type `never`?".
- **`Object.freeze`**: at runtime the helper only freezes the array, so it can't be mutated.

Result: if you add, rename or remove an enum value in the spec and regenerate, `npm run
typecheck` fails until `index.ts` matches.

## 3. Python: generated models and `app.contracts`

### Generated Pydantic models

`datamodel-codegen` reads its configuration from `[tool.datamodel-codegen]` in
[apps/backend/pyproject.toml](apps/backend/pyproject.toml) and writes
[app/generated/contract_models.py](apps/backend/app/generated/contract_models.py):

```python
class WorkOrderState(StrEnum):
    reported = "reported"
    triaged = "triaged"
    ...

class WorkOrder(BaseModel):
    id: Annotated[str, Field(min_length=1)]
    ...
```

Key generator options:

| Option | Effect |
| --- | --- |
| `output-model-type = "pydantic_v2.BaseModel"` | Pydantic v2 models |
| `use-annotated`, `field-constraints` | `minLength` becomes `Annotated[str, Field(min_length=1)]` |
| `use-union-operator` | nullable fields are written `str \| None` |
| `disable-timestamp`, `formatters = ["ruff-format", "ruff-check"]` | output is byte-for-byte reproducible, which the drift guard relies on |

Ruff skips `app/generated/`, but mypy (strict) still type-checks it.

### Public entry point

[app/contracts.py](apps/backend/app/contracts.py) re-exports every generated model **unchanged**
and builds the runtime tuples **from the generated enums**, so they cannot drift:

```python
STATES: Final[tuple[WorkOrderState, ...]] = tuple(WorkOrderState)
ACTIONS: Final[tuple[WorkOrderAction, ...]] = tuple(WorkOrderAction)
PRIORITIES: Final[tuple[Priority, ...]] = tuple(Priority)
```

- `tuple(Enum)` iterates the members in definition order, which is the contract's order.
- The enums are `StrEnum`s, so `WorkOrderState.reported == "reported"` is `True`, and the tuples
  compare equal to plain string tuples.
- `Final` plus an immutable `tuple` mirrors the frozen TypeScript arrays.

## 4. Drift guard: `verify:contract`

Generated files are committed, so someone could edit `openapi.yaml` and forget to regenerate.
[scripts/verify-contract.mjs](scripts/verify-contract.mjs) catches that:

```js
const tmp = mkdtempSync(join(generator.tmpParent, '.verify-contract-'));
fresh = readFileSync(generator.generate(tmp));        // regenerate into a temp dir
...
const ok = committed?.equals(fresh) ?? false;         // byte-for-byte comparison
console.log(`  ${ok ? 'ok   ' : 'STALE'}  ${generator.committed}`);
```

- It runs both generators with the **same settings** as the `contract:generate:*` scripts, and
  changes only the output path. It never writes to the working tree.
- Commands run through `spawnSync` **without a shell**, so paths with spaces work.
- The Python temp directory is created **inside `apps/backend`**. The ruff post-formatter reads
  settings such as line length from the nearest `pyproject.toml`, so under the OS temp dir it
  would fall back to ruff's defaults and never match.
- It exits non-zero and lists each stale file, and `npm run verify` runs it first.

## 5. Contract smoke tests

These are fast checks that the runtime values each language exposes match the contract. They
back up the compile-time checks: the TypeScript compiler can't see duplicates, for example.

### TypeScript (Vitest)

[packages/contract/src/index.test.ts](packages/contract/src/index.test.ts)

```ts
it('STATES includes all six states', () => {
  expect(STATES).toHaveLength(6);
  expect(STATES).toEqual(
    expect.arrayContaining([
      'reported', 'triaged', 'scheduled', 'in_progress', 'completed', 'cancelled',
    ]),
  );
});
```

- `expect.arrayContaining` checks that every expected value is present **in any order**.
- `toHaveLength` adds the missing half: with the exact length, no unexpected extra value can
  slip in. The `ACTIONS` (5) and `PRIORITIES` (4) tests follow the same pattern.

```ts
it.each([
  ['STATES', STATES],
  ['ACTIONS', ACTIONS],
  ['PRIORITIES', PRIORITIES],
] as const)('%s contains no duplicates', (_name, values) => {
  expect(new Set(values).size).toBe(values.length);
});
```

- `it.each` produces one named test per array; `%s` is replaced by the first element.
- A `Set` drops duplicates, so if its size equals the array length, every value is unique.
- `as const` keeps the tuple types precise, which the strict ESLint and TypeScript settings need.

The test file sits in `src/`, so `npm run typecheck` and `npm run lint` check it like any
other source file.

### Python (pytest)

[apps/backend/tests/test_contract_smoke.py](apps/backend/tests/test_contract_smoke.py)

```python
def test_generated_models_import() -> None:
    module = importlib.import_module("app.generated.contract_models")
    for name in ("Asset", "Technician", "WorkOrder", ...):
        assert issubclass(getattr(module, name), BaseModel)
```

- It imports the generated module **dynamically**, so a broken or missing file fails this named
  test instead of an error during collection.
- It checks that each expected model exists **and** is a Pydantic `BaseModel`.

```python
def test_contracts_expose_enum_values() -> None:
    assert set(contracts.STATES) == {"reported", "triaged", "scheduled", ...}
```

- It compares against plain strings. That works because the members are `StrEnum`s.
- Set equality means every value is present and nothing unexpected is there.

```python
@pytest.mark.parametrize("name", ["STATES", "ACTIONS", "PRIORITIES"])
def test_runtime_tuples_have_no_duplicates(name: str) -> None:
    values: tuple[str, ...] = getattr(contracts, name)
    assert len(set(values)) == len(values)
```

- `parametrize` produces one test per tuple, reported as
  `test_runtime_tuples_have_no_duplicates[STATES]` and so on.

### Running only the contract tests

```bash
# TypeScript
npx --workspace @equipment-maintenance-hub/contract vitest run src/index.test.ts

# Python
uv run --directory apps/backend pytest tests/test_contract_smoke.py -v
```

Expected output: `Tests 6 passed (6)` for Vitest and `5 passed` for pytest. `npm test` runs the
full suites of both ecosystems.
